## Why a plain `<script>` blocks the parser

By default, the HTML parser treats `<script src="...">` as "stop everything until this downloads and runs" — the browser has no way to know in advance whether that script is going to modify the page (via `document.write`, for instance), so it plays it safe and halts. The same is true for `<link rel="stylesheet">`: the browser withholds paint until it knows the full set of styles that could apply, since rendering with the wrong styles and then repainting would be worse than the wait.

## `async` vs. `defer`

```html
<script src="analytics.js" async></script>
<script src="app.js" defer></script>
```

- **`async`** downloads in parallel with parsing and executes the moment it finishes — which could be before parsing is done, interrupting it. Good for independent scripts with no dependency on the DOM being fully built (analytics, ads).
- **`defer`** also downloads in parallel, but always waits until parsing completes, and multiple `defer` scripts always run in their original document order. Good for scripts that need the full DOM or need to run in a specific order relative to each other.

## Resource hints don't change execution — only fetch timing

```html
<link rel="preconnect" href="https://api.example.com" />
<link rel="preload" href="/fonts/inter.woff2" as="font" crossorigin />
<link rel="prefetch" href="/next-page-chunk.js" />
```

- **`preconnect`** opens the DNS/TCP/TLS connection to a host ahead of the first real request to it — useful when you know you'll fetch from that origin soon but don't have the exact URL yet.
- **`preload`** fetches a specific resource the browser wouldn't otherwise discover until later in parsing (a font referenced only inside CSS, for example) — critical, above-the-fold resources.
- **`prefetch`** is a low-priority hint for something the *next* navigation will likely need, not this page — the browser fetches it when bandwidth is idle.

## Putting it together

The real optimization goal is keeping the render-blocking set as small as possible: only the CSS and scripts genuinely required for first paint should block; everything else should be `async`, `defer`, or moved out of the critical path entirely with a resource hint.
