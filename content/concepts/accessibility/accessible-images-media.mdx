## Writing alt text that actually helps

Good alt text answers "what is this image communicating," not "what does this image literally show":

```html
<!-- Bad: describes the file, not the content -->
<img src="chart-q3.png" alt="chart" />

<!-- Good: describes what the image is communicating -->
<img src="chart-q3.png" alt="Q3 revenue grew 18% over Q2, driven mostly by the new enterprise tier" />
```

For a functional image — one inside a link or button, where the image itself IS the control — alt text should describe the destination or action, not the picture:

```html
<a href="/cart">
  <img src="cart-icon.svg" alt="View shopping cart" />
</a>
```

## Decorative images get an empty alt, on purpose

If an image adds nothing informational — a stylistic squiggle, a repeated background pattern — mark it decorative:

```html
<img src="divider-swirl.svg" alt="" />
```

This is different from forgetting alt entirely. `alt=""` is parsed correctly and skipped; a missing `alt` attribute often causes the screen reader to read out the raw `src` filename instead, which is worse than saying nothing.

## Complex images need more than one line of alt text

A chart, diagram, or infographic usually can't be summarized in a short alt attribute. The common pattern: a short `alt` that names what the image is, plus the same information available as real text nearby (a data table, a paragraph summary) that everyone — not just screen reader users — can read.

## Video needs captions, audio needs a transcript

- **Captions** are text synced to a video's timeline, covering both dialogue and important non-speech sound ("[phone ringing]"). They serve deaf/hard-of-hearing users and anyone watching without sound.
- **Transcripts** are a full text version of audio-only content (a podcast, a voice memo) — there's no timeline to sync to, so it's just the complete text, often with speaker labels.

A video can have both: captions for real-time viewing, and a full transcript underneath for scanning, searching, or translation.

## Icon-only buttons still need an accessible name

An icon with no visible text label needs an accessible name from somewhere — either `aria-label` on the button, or visually-hidden text inside it, with the icon itself marked `aria-hidden="true"` so it isn't announced twice:

```html
<button aria-label="Close dialog">
  <svg aria-hidden="true">...</svg>
</button>
```
