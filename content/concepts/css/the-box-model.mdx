## The four layers

Every box is built from the inside out:

1. **Content** — where text and child elements actually render, sized by `width`/`height`.
2. **Padding** — transparent space between the content and the border; it's part of the element itself and shares its background color.
3. **Border** — a visible (or invisible) line drawn around the padding.
4. **Margin** — transparent space *outside* the border, separating this box from its neighbors. Margin never has a background — it's pure separation.

```
┌─────────────── margin ───────────────┐
│ ┌──────────── border ──────────────┐ │
│ │ ┌──────── padding ─────────────┐ │ │
│ │ │        content (w × h)        │ │ │
│ │ └──────────────────────────────┘ │ │
│ └───────────────────────────────────┘ │
└─────────────────────────────────────────┘
```

## content-box vs. border-box

The `box-sizing` property decides what `width`/`height` actually measure:

- **`content-box`** (the CSS default) — `width` is the content only. Padding and border are added *on top*, so the box grows larger than its declared width the moment you add either.
- **`border-box`** — `width` is the content + padding + border combined. Adding padding or border shrinks the content area instead of growing the box, so the element's outer size stays exactly what you declared.

```css
.card {
  width: 200px;
  padding: 20px;
  border: 2px solid;
}
/* content-box (default): rendered width = 200 + 20*2 + 2*2 = 244px */
/* border-box:            rendered width = 200px, content area = 156px */
```

This is why almost every real-world CSS reset includes `*, *::before, *::after { box-sizing: border-box; }` — it makes declared sizes predictable regardless of how much padding or border gets added later.

## Margin collapsing

Vertical margins between adjacent block-level siblings **collapse** into a single margin equal to the larger of the two, rather than adding together. A paragraph with `margin-bottom: 20px` followed by one with `margin-top: 30px` ends up with 30px of space between them, not 50px. Horizontal margins never collapse, and margin collapsing only happens in normal document flow — it doesn't apply inside a flex or grid container.

## Why it matters

Every layout bug that looks like "this element is bigger than I told it to be" traces back to the box model — either a missing `box-sizing: border-box`, or forgetting that margin sits outside the border and doesn't count toward the element's own width.
