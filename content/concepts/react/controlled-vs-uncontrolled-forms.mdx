## Controlled: React owns the value

```jsx
function ControlledInput() {
  const [value, setValue] = useState("");
  return <input value={value} onChange={(e) => setValue(e.target.value)} />;
}
```

Every render, the input's displayed text is exactly `value` — nothing else can change it. This makes validation, formatting-as-you-type, and conditionally disabling submit trivial, because state is always the single source of truth.

## Uncontrolled: the DOM owns the value

```jsx
function UncontrolledInput() {
  const inputRef = useRef(null);
  const handleSubmit = (e) => {
    e.preventDefault();
    console.log(inputRef.current.value);
  };
  return (
    <form onSubmit={handleSubmit}>
      <input ref={inputRef} defaultValue="" />
    </form>
  );
}
```

The input manages its own internal value the way a plain `<input>` always has. React never re-renders on keystroke — it only reaches in and reads the current value through the ref when something else (a submit handler) asks for it.

## Why mixing them causes a warning

```jsx
<input value={value} /> // value starts as undefined, then later becomes "abc"
```

If `value` starts as `undefined`, React treats the input as uncontrolled on the first render. The moment `value` becomes a real string on a later render, React sees the source of truth flip mid-lifetime and warns — this is almost always caused by state initialized to `undefined`/`null` instead of an empty string.

## Choosing between them

- **Controlled** — when you need to validate on every keystroke, format input live (currency, phone numbers), or conditionally enable/disable other UI based on the value.
- **Uncontrolled** — for a simple form read once on submit, or when integrating a non-React widget that manages its own DOM value already (many rich-text editors, some date pickers).

## Why it matters

Most "my input feels laggy" or "cursor jumps to the end while typing" bugs in production React apps trace back to a controlled input whose `onChange` does something expensive (or asynchronous) before calling `setValue` — the render that shows your keystroke is now waiting on that work to finish.
