## Catching errors with a class component

```jsx
class ErrorBoundary extends React.Component {
  state = { hasError: false };
  static getDerivedStateFromError(error) {
    return { hasError: true }; // triggers the fallback render
  }
  componentDidCatch(error, info) {
    logErrorToService(error, info); // side effect: reporting
  }
  render() {
    if (this.state.hasError) return this.props.fallback;
    return this.props.children;
  }
}

<ErrorBoundary fallback={<p>Something went wrong.</p>}>
  <Dashboard />
</ErrorBoundary>
```

If any component inside `<Dashboard />` throws during render, React unmounts that whole subtree and renders `fallback` in its place — everything outside the boundary keeps working normally.

## What it does and doesn't catch

**Catches:**
- Errors thrown during rendering
- Errors in lifecycle methods (`componentDidMount`, etc.)
- Errors in constructors of the tree below it

**Does not catch:**
- Errors inside event handlers (`onClick`, `onChange`) — these need a plain `try/catch` at the call site
- Errors in asynchronous code (`setTimeout`, promises) — the error boundary has no way to associate a later-firing callback with the render it interrupted
- Errors during server-side rendering
- Errors thrown in the error boundary component itself (a parent boundary would need to catch those)

## Granularity is a design decision

Wrapping the entire app in one boundary means any single widget's crash blanks the whole page. Wrapping each independent section (a dashboard's individual widgets, a feed's individual posts) in its own boundary means one broken widget shows its own fallback while everything else keeps rendering normally — a resilience tradeoff made by *where* boundaries are placed, not by how they're implemented.

## Why it matters

"Why did my error boundary not catch this" is one of the most common React support questions, and it's almost always one of the two exclusions above — an event handler or an async callback. Recognizing which kind of error you're looking at is the actual skill being tested, not memorizing the class component syntax.
