## React.memo: skip re-rendering a component

```jsx
const ExpensiveRow = React.memo(function ExpensiveRow({ item }) {
  return <tr>{item.name}</tr>;
});
```

Wrapped in `memo`, `ExpensiveRow` only re-runs its render if `item` (compared shallowly, by reference for objects) is different from last time — even if its parent re-renders. Passing a brand-new object or inline function as a prop every render defeats this entirely, since a new reference always fails the shallow-equality check.

## useMemo: skip recomputing a value

```jsx
const sortedItems = useMemo(
  () => [...items].sort((a, b) => a.price - b.price),
  [items],
);
```

Without `useMemo`, this sort re-runs on *every* render of the component, even ones triggered by something totally unrelated (like a sibling's state). `useMemo` re-runs the calculation only when `items` changes.

## useCallback: skip recreating a function

```jsx
const handleClick = useCallback(() => onSelect(item.id), [onSelect, item.id]);
```

Every render normally creates a brand-new function — harmless on its own, but a problem if that function is passed as a prop to a `memo`-wrapped child: a new function reference makes the child's shallow-equality check fail every time, defeating its memoization. `useCallback` keeps the same function reference across renders until its dependencies change.

## The profiling-first rule

These three APIs only pay off when: (1) the wrapped component/calculation is actually expensive, and (2) it re-renders/recalculates often with props/inputs that are actually the same. Adding them everywhere "to be safe" adds real overhead (extra comparisons, extra memory) to every render, for optimizations that often never pay off — the React team's own guidance is to reach for the Profiler first, find an actual slow re-render, and only then memoize the specific thing causing it.

## Why it matters

An interviewer asking "would you add useMemo here?" is rarely testing whether you know the syntax — they're testing whether you'd measure first. The correct answer to "should everything be memoized" is almost always no.
