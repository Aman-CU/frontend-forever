## useState: memory across renders

A regular variable resets every time a component function re-runs. `useState` gives a value that React remembers between renders, and a setter that schedules a re-render when called:

```jsx
function Counter() {
  const [count, setCount] = useState(0);
  return <button onClick={() => setCount(count + 1)}>{count}</button>;
}
```

Calling `setCount` doesn't mutate `count` in place — it tells React "re-render this component, and next time give it this new value instead."

## useEffect: syncing with the outside world

`useEffect` runs *after* React has committed the render to the DOM — it's for anything that isn't itself a description of UI: subscribing to an event, starting a timer, fetching data.

```jsx
useEffect(() => {
  const id = setInterval(() => setCount((c) => c + 1), 1000);
  return () => clearInterval(id); // cleanup, runs before the next effect and on unmount
}, []); // dependency array
```

## The dependency array's three modes

```js
useEffect(() => { ... });          // no array: runs after every render
useEffect(() => { ... }, []);      // empty array: runs once, after the first render
useEffect(() => { ... }, [id]);    // runs after the first render, and again whenever `id` changes
```

React compares each dependency to its previous value with `Object.is` — the same value means the effect is skipped this render.

## Why "stale closures" happen

An effect's function closes over the values from the render it was created in. If a dependency it reads isn't listed, the effect keeps using the *original* value from mount, even after that value has changed elsewhere in the component — the classic "stale closure" bug. The fix is always to include every value the effect reads in the dependency array, not to suppress the lint warning.

## Why it matters

Almost every React bug report that starts with "this only works on the first render" or "this fires infinitely" traces back to a dependency array that doesn't actually match what the effect reads. Getting the mental model right here — sync, not lifecycle — prevents most of them before they happen.
