## Suspense: a standard way to say "not ready yet"

```jsx
const ProfilePage = React.lazy(() => import("./ProfilePage"));

<Suspense fallback={<Spinner />}>
  <ProfilePage />
</Suspense>
```

`React.lazy` throws a Promise while the module is still downloading. The nearest `<Suspense>` ancestor catches it, renders `fallback` instead, and automatically retries rendering `ProfilePage` once the Promise resolves. Data-fetching libraries (Relay, React Query's Suspense mode) use the same mechanism for data, not just code-split components.

## useTransition: marking an update as low-priority

```jsx
function SearchPage() {
  const [isPending, startTransition] = useTransition();
  const [query, setQuery] = useState("");
  const [results, setResults] = useState([]);

  function handleChange(e) {
    setQuery(e.target.value); // urgent: keep the input responsive
    startTransition(() => {
      setResults(searchSync(e.target.value)); // low-priority: can be interrupted
    });
  }
  return <>{isPending && <Spinner />}<input value={query} onChange={handleChange} /></>;
}
```

Without `startTransition`, a slow `setResults` update would block the input from visually updating until it finished — every keystroke would feel laggy. Wrapping it marks that update as interruptible: if the user types again before it finishes, React abandons the stale in-progress render and starts fresh with the latest input, while the input itself stays instantly responsive throughout.

## Why this needed a new rendering model

None of this is possible with a synchronous, uninterruptible renderer — once a render started, React had no way to check "did something more urgent just arrive?" partway through. Concurrent React restructures the render phase so it *can* pause, check, and either resume or restart, which is also what makes streaming SSR (rendering and sending HTML in chunks as data becomes ready) possible.

## Why it matters

These features solve a specific, real problem — expensive updates making an app feel unresponsive during rapid input — rather than being a general "turn on for more performance" switch. Interviewers asking about Suspense/transitions are usually checking whether you can identify *when* interruptibility actually helps, not whether you've memorized the hook names.
