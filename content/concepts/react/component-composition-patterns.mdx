## `props.children`: the simplest composition

```jsx
function Card({ children }) {
  return <div className="card">{children}</div>;
}
<Card><h2>Title</h2><p>Body text</p></Card>
```

`Card` has no idea what it's rendering inside — it just provides a container. This is composition's most basic form: a parent supplies structure, the caller supplies content.

## Render props: sharing logic, not markup

```jsx
function MouseTracker({ render }) {
  const [pos, setPos] = useState({ x: 0, y: 0 });
  return (
    <div onMouseMove={(e) => setPos({ x: e.clientX, y: e.clientY })}>
      {render(pos)}
    </div>
  );
}
<MouseTracker render={(pos) => <p>{pos.x}, {pos.y}</p>} />
```

`MouseTracker` owns the stateful logic (tracking the mouse) but has no opinion on what the coordinates are rendered as — the caller's function decides. Most render-prop use cases today are handled by custom hooks instead (the next concept in this path), which don't require wrapping output in an extra component.

## Compound components: implicit shared state

```jsx
<Tabs defaultValue="profile">
  <Tabs.List>
    <Tabs.Trigger value="profile">Profile</Tabs.Trigger>
    <Tabs.Trigger value="settings">Settings</Tabs.Trigger>
  </Tabs.List>
  <Tabs.Panel value="profile">...</Tabs.Panel>
  <Tabs.Panel value="settings">...</Tabs.Panel>
</Tabs>
```

`Tabs` provides a Context holding the active tab; `Tabs.Trigger` and `Tabs.Panel` both read from it. The caller never passes `activeTab`/`onTabChange` between siblings manually — the components coordinate through Context internally, while the JSX still reads like plain markup.

## Choosing between them

- **Children** — when a component is purely a layout/container with no shared state to coordinate.
- **Render props** (or a custom hook) — when a component owns stateful *logic* but the caller should fully control the rendering.
- **Compound components** — when several components need to share hidden state and you want the calling code to read like natural nested markup (most component libraries' `Select`, `Tabs`, `Accordion` APIs use this).

## Why it matters

Reaching for prop drilling or a giant configuration-object prop when one of these three patterns fits better is one of the most common signs of unfamiliarity with idiomatic React composition — interviewers often ask "how would you design this component's API" specifically to see which of these three you reach for.
