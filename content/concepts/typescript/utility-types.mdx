## Deriving instead of redefining

Without utility types, a variant of an existing shape means hand-writing a second, separate type that has to be kept in sync manually:

```ts
type User = { id: string; name: string; email: string };

// hand-written variant — has to be updated by hand if User changes
type UserDraft = { id?: string; name?: string; email?: string };
```

Utility types compute the variant from the source type instead, so it updates automatically the moment the source does.

## Partial\<T\>

Makes every property of `T` optional:

```ts
type UserDraft = Partial<User>;
// { id?: string; name?: string; email?: string }
```

Common for "update" payloads, where a caller only sends the fields that changed, and for objects built up incrementally across multiple steps before every field is filled in.

## Pick\<T, K\>

Keeps only the listed keys `K` (a union of string literals) from `T`:

```ts
type UserPreview = Pick<User, "id" | "name">;
// { id: string; name: string }
```

Useful for a narrower view of a large type — a list item that only needs a few fields from a much bigger record.

## Omit\<T, K\>

The inverse of `Pick` — keeps every key of `T` except the listed ones:

```ts
type UserCreateInput = Omit<User, "id">;
// { name: string; email: string }
```

Common for "create" payloads, where the server assigns a field (like `id`) that the client should never provide.

## Record\<K, V\>

Builds an object type from a union of keys `K`, each mapped to the same value type `V` — the one utility here that isn't derived from an existing object type, but constructed from a key list:

```ts
type Role = "admin" | "editor" | "viewer";
type RolePermissions = Record<Role, string[]>;
// { admin: string[]; editor: string[]; viewer: string[] }
```

## Composing them together

Utility types combine freely, since each one just takes a type and returns a type:

```ts
type UserUpdateInput = Partial<Omit<User, "id">>;
// every field except id, and every remaining field optional
```

## Why it matters

Utility types keep derived shapes honest — the moment `User` gains a new field, `Pick<User, "id" | "name">` and `Partial<User>` update automatically, with no hand-maintained duplicate type to forget about. A hand-written variant type is a second source of truth waiting to drift out of sync.
