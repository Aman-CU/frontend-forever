## The problem generics solve

A function locked to one type can't be reused for another, even when the logic is identical:

```ts
function firstNumber(arr: number[]): number { return arr[0]; }
function firstString(arr: string[]): string { return arr[0]; }
// same logic, duplicated per type
```

The tempting shortcut — typing the parameter `any` — throws away the guarantee entirely: `first(arr: any): any` compiles for every input, but also silently accepts and returns garbage with no error anywhere.

## Generic type parameters

A generic type parameter fills in the gap between "one exact type" and "any type, unchecked":

```ts
function first<T>(arr: T[]): T {
  return arr[0];
}

first([1, 2, 3]);       // T inferred as number, returns number
first(["a", "b"]);      // T inferred as string, returns string
```

TypeScript infers `T` from the argument at the call site — no need to write `first<number>([1, 2, 3])` explicitly unless inference genuinely can't determine it. Once `T` is fixed for that call, every other place `T` appears in the signature is held to the same type.

## Constraining generics with extends

An unconstrained `T` can be *any* type, which sometimes allows too much — `T extends U` narrows the generic to only types compatible with `U`:

```ts
function pluck<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}

pluck({ name: "Ada", age: 36 }, "name"); // fine — "name" is a real key
pluck({ name: "Ada", age: 36 }, "email"); // compile error — no "email" key
```

`K extends keyof T` says "`K` must be one of `T`'s actual property names" — the constraint is what makes `pluck` reject a typo'd key at compile time instead of returning `undefined` at runtime.

## Multiple type parameters

A signature can declare more than one generic parameter, each inferred independently from a different argument:

```ts
function merge<A, B>(a: A, b: B): A & B {
  return { ...a, ...b };
}

merge({ name: "Ada" }, { age: 36 }); // { name: string } & { age: number }
```

## Why it matters

Generics are what let a library ship one `Array.prototype.map`, one `Promise<T>`, one `useState<T>` instead of a hand-duplicated version per type — the entire standard library and most well-typed utility functions lean on generics to stay both reusable and precisely typed at the same time.
