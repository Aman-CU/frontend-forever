## What a Promise actually is

A **Promise** is an object representing a value that will be available later. It exists in exactly one of three states:

- **pending** — not yet settled
- **fulfilled** — settled successfully, with a value
- **rejected** — settled with a failure reason

Once a Promise settles (fulfilled or rejected), it stays that way forever — it can't go back to pending or settle a second time.

```js
const promise = new Promise((resolve, reject) => {
  setTimeout(() => resolve("done"), 1000);
});

promise.then((value) => console.log(value)); // "done", after ~1s
```

## Chaining and combining

`.then()` returns a *new* Promise, which is what makes chaining work — each `.then()` can return a plain value or another Promise, and the chain waits for it either way:

```js
fetchUser(id)
  .then((user) => fetchPosts(user.id))
  .then((posts) => console.log(posts))
  .catch((err) => console.error(err));
```

For running multiple Promises together, the static combinators each answer a different question: `Promise.all` waits for every one to fulfill (rejects immediately if any rejects), `Promise.allSettled` waits for every one regardless of outcome, `Promise.race` settles as soon as the first one settles, and `Promise.any` fulfills as soon as the first one fulfills.

## async/await is syntax over Promises

`async`/`await` doesn't replace Promises — every `async function` returns a Promise, and `await` is just a different way of consuming one:

```js
async function loadUser(id) {
  const user = await fetchUser(id);   // pauses here until fetchUser's promise settles
  const posts = await fetchPosts(user.id);
  return posts;
}
```

This reads like synchronous code, but nothing is actually blocked — `await` suspends only the `async function` itself, hands control back to whatever called it, and resumes the function's remaining body as a microtask once the awaited Promise settles (the event loop concept covers exactly how that scheduling works).

## Error handling

`.catch()` on a Promise chain and `try/catch` around `await` handle the same thing — a rejected Promise:

```js
try {
  const user = await fetchUser(id);
} catch (err) {
  console.error("failed to load user:", err);
}
```

A rejected Promise with no `.catch()`/`try-catch` anywhere in its chain surfaces as an "unhandled promise rejection," which most runtimes log loudly — always give every async operation a path to handle failure.
